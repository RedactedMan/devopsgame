The design model behind Flow State's planned "Rubber Stamp" level · docs/GAME_DESIGN.md §4.6

This is the model the game uses for agent review, and it's the next level we're building. It isn't in today's version yet. Agent review is real and worth having. It catches the mechanical defects, which are most of the volume. What it misses are design defects, the wrong abstraction or a misread requirement, and integration defects, where one change collides with other work in flight. Those are the ones that cause outages. The trap: an agent-approved change looks verified, so it skips the human queue. Displayed quality goes up and true quality doesn't, and a few weeks later the change failure rate tells you. That's Goodhart's Law: approval counts can be satisfied cheaply, so they will be. The table is the game's design model, not a measured study. Present it as a way of thinking, and note the CodeRabbit finding that logic and correctness issues were the biggest category.
