"Nobody read the code"

WHAT CHANGED

"None of these things have intuition for software architecture." He no longer thinks skipping review pays off, now that agents write 10x to 100x more code.

Dex Horthy, "Context engineering with Dex Horthy", The Pragmatic Engineer, 15 Jul 2026, 44:01 to 45:39

This one is about review itself. Dex Horthy's team turned the lights off: if a user complained, an agent got it; if something crashed, an agent got it; and because humans couldn't keep up with the volume, they replaced PR review with agentic testing and agentic code review. In his words, "none of these things have intuition for software architecture because we haven't trained it in yet." About three months in, production broke, and no amount of expert prompting got Opus 4.1 to find the root cause. It took several days of people digging through the code to find it: a primary key routed through the whole system that needed to become a different kind of object with its own table. That's a design defect, the class on the agent review slide that agents miss. Then three weeks re-onboarding to a codebase nobody had read. At the time he thought it was still worth it. He doesn't anymore, because the amount of code agents write now is "like 10x or 100x", and the problem is getting worse. This is why the game doesn't let agents staff Review. Our own reviewers use AI tools and they catch a lot, but whether a change is right is still a person's call, going by these cases and what I've seen on my own teams. He says three months in the episode; the episode summary says four. The slide goes with his own words.
